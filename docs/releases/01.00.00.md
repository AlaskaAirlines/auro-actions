# Release Notes

This document outlines all changes up to the 1.0.0 release. There is no previous release; 1.0.0 is the first version of auro-actions.

Version 1.0.0 is the **first versioned release** of auro-actions, focused on stamping `custom-elements.json` with its package identity, splitting tests into parallel jobs, automating release candidates, and putting auro-actions itself on the Auro git flow. No breaking API changes for repositories already calling the workflows at `@main`.

## Summary

Until now, changes to auro-actions reached every Auro repository as soon as they merged to `main`, with no tag or release to track or roll back to. Starting with 1.0.0, auro-actions follows the same `dev` → `rc/*` → `main` flow as Auro components, and each release that affects consuming repositories gets a `vX.Y.Z` tag and GitHub release. Consuming repositories still call the workflows at `@main`. This release also collects the reusable workflow features and fixes that landed on `main` before versioning started.

- `pull-request.yml` and `release.yml` set `"package": "<name>@<version>"` in `custom-elements.json` before publishing, so every published manifest says which package build it describes.
- `pull-request.yml` and `release.yml` accept a `test-matrix` input to split tests into parallel jobs, an `additional-build-command` input that runs after the build, and report a single `test-results` check for branch rules.
- `release-candidate.yml` creates and updates the `rc/<ticket id>` branch and `RC #<ticket id>` pull request on every push to `dev`.
- `sync-tags.yml` fast-forwards `dev` to `main` after a release, and fails with a readable error when it can't.
- `check-pr.yml` requires one approving review on breaking-change pull requests, down from two.

All changes are backward compatible. Repositories that use `release-candidate.yml` or `sync-tags.yml` must pass the `GH_TOKEN` and `ADO_TOKEN` secrets described in the [README](../../README.md#required-secrets). Repositories that added an `@semantic-release/exec` step to stamp `custom-elements.json` should remove it (see below).

## Features

### PULL-REQUEST.YML / RELEASE.YML

- **Stamp the package name and version into `custom-elements.json`** — [AB#1665681](https://itsals.visualstudio.com/5e9f12eb-f830-406f-bee9-be25938f7aaa/_workitems/edit/1665681), [#13](https://github.com/AlaskaAirlines/auro-actions/pull/13), [#14](https://github.com/AlaskaAirlines/auro-actions/pull/14)

    Published manifests did not say which package or version they came from. `pull-request.yml` now writes `"package": "<name>@<version>"` after `auro pr-release` sets the PR version and before `npm publish`. `release.yml` runs `npx semantic-release --dry-run` first, reads the version from its `The next release version is X` line, and stamps the file before the real release. The step skips when no release is due or the file is missing, and fails if the dry run fails. No per-repo setup is needed. An earlier README revision told repositories to add an `@semantic-release/exec` plugin for this. If you added it, remove it, since the shared workflow now does the same thing. The release stamp depends on semantic-release's log wording, so check it after semantic-release upgrades.

- **Split tests into parallel jobs with `test-matrix`** — [AB#1568829](https://itsals.visualstudio.com/5e9f12eb-f830-406f-bee9-be25938f7aaa/_workitems/edit/1568829), [#4](https://github.com/AlaskaAirlines/auro-actions/pull/4)

    A JSON array of `{ name, command }` slices, each run as its own job on every Node version in the matrix. The default is a single `npm run test` job, so existing callers keep their current behavior.

- **Run an extra command after the build with `additional-build-command`** — [AB#1568829](https://itsals.visualstudio.com/5e9f12eb-f830-406f-bee9-be25938f7aaa/_workitems/edit/1568829), [#5](https://github.com/AlaskaAirlines/auro-actions/pull/5)

    Runs after the build and before the build output is cached, for example `npx playwright install chromium`. Defaults to empty.

- **Add a `test-results` gate job** — [#6](https://github.com/AlaskaAirlines/auro-actions/pull/6)

    With `test-matrix`, check names change as slices are added or renamed. `test-results` always runs and fails unless every test job succeeded, so branch rules can require one stable check.

### RELEASE-CANDIDATE.YML

- **Create release candidates automatically** — [#9](https://github.com/AlaskaAirlines/auro-actions/pull/9)

    On every push to `dev`, runs `auro rc-workflow`, which finds the `auro-rcs` Release ticket linked to the new commits and creates or updates the `rc/<ticket id>` branch and `RC #<ticket id>` pull request into `main`. Callers pass `ADO_TOKEN` (required, to resolve the Release ticket) and `GH_TOKEN` (optional, falls back to `GITHUB_TOKEN`).

## Bug Fixes

_Note: Bug fixes do not require migration steps. Updating to this version is all that is necessary to implement these changes._

### SYNC-TAGS.YML

- **Fast-forward `dev` to `main` with guardrails** — [AB#1643314](https://itsals.visualstudio.com/5e9f12eb-f830-406f-bee9-be25938f7aaa/_workitems/edit/1643314), [#10](https://github.com/AlaskaAirlines/auro-actions/pull/10)

    The sync relied on a fragile `git describe --exact-match` tag lookup and pushed with `GITHUB_TOKEN`, which the `dev` branch ruleset rejects. It now fast-forwards `dev` to `origin/main`, exits cleanly when `dev` is already up to date, and fails with the list of divergent commits when a fast-forward isn't possible. It checks out with `GH_TOKEN` and uses a per-repository concurrency group so overlapping releases can't race. Releases published by a bot don't start workflows, so callers now trigger it on push to `main`, with `workflow_dispatch` as a fallback.

### RELEASE-CANDIDATE.YML

- **Detect new `dev` commits reliably** — [#9](https://github.com/AlaskaAirlines/auro-actions/pull/9)

    The check for commits on `dev` that are not yet on `main` now uses a GitHub script, and the workflow logs whether it found new commits and an existing RC branch.

### CHROMATIC.YML

- **Enable TurboSnap** — [#3](https://github.com/AlaskaAirlines/auro-actions/pull/3)

    Chromatic runs with `onlyChanged` (TurboSnap), so it only snapshots stories affected by the change. The workflow also handles pushes to `dev`.

## Build & Packaging

- **Require one approving review on breaking changes** — [#11](https://github.com/AlaskaAirlines/auro-actions/pull/11)

    `check-pr.yml` now requires one approving review, down from two, on pull requests labeled `semantic-status: breaking`. The sticky PR comment states the new threshold.

- **Run auro-actions on the Auro git flow** — [AB#1666417](https://itsals.visualstudio.com/5e9f12eb-f830-406f-bee9-be25938f7aaa/_workitems/edit/1666417), [#15](https://github.com/AlaskaAirlines/auro-actions/pull/15)

    auro-actions now runs its own pull request, commit, review policy, RC, release, tag sync, and CodeQL automation through `repo-*.yml` caller workflows. They call the reusable workflows through local paths, so a pull request tests its own workflow changes. semantic-release creates tags and GitHub releases only; the package is private and nothing is published to npm. Each caller workflow grants only the `GITHUB_TOKEN` permissions its reusable workflow needs. `.releaserc` and `.commitlintrc` extend auro-config, and a commit-msg hook enforces Conventional Commits.
